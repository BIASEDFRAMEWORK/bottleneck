# AI Implementation Prompt: Trend Analysis From Local Snapshots

You are working in the Bottleneck Go CLI codebase.

Implement **Implementation Epic 2: Trend analysis from local snapshots** from the `Enterprise SDLC Evidence Package` milestone.

## Milestone Context

Bottleneck should help teams explain SDLC evidence over time without a database, SaaS backend, dashboard, or external storage. Git and local files are the system of record.

This epic adds:

```sh
bottleneck trends
```

The command reads local scorecard snapshots, compares evidence across time, and reports whether the team is improving, declining, stable, recovered, regressed, or lacks enough history.

## Default Behavior

When the user runs:

```sh
bottleneck trends
```

Bottleneck should:

1. Read snapshots from `bottleneck/history/scorecards/`.
2. Filter to environment `default`.
3. Sort by `snapshot.created_at` ascending.
4. Use the latest 6 snapshots by default.
5. Compare category scores and statuses.
6. Identify category directions.
7. Identify the persistent primary bottleneck.
8. Generate an overall direction.
9. Render a text trend summary to stdout.

No database or external service should be used.

## Score Extraction

Use numeric category scores if the scorecard JSON already has them.

If category scores are missing, normalize statuses:

```text
PASS = 100
WARN = 60
FAIL = 0
UNKNOWN = null
```

Trends should be resilient to older snapshots with missing optional fields. Handle missing values explicitly and report insufficient data rather than panicking.

## Direction Rules

Given a category's first and last score in the selected window:

```text
delta = last - first
```

Rules:

- Fewer than 2 snapshots: `insufficient_history`
- `delta >= +10`: `improving`
- `delta <= -10`: `declining`
- `abs(delta) < 10`: `stable`

Special classifications:

- `recovered`: category had `FAIL` or `WARN` earlier and latest is `PASS`
- `regressed`: category had `PASS` earlier and latest is `WARN` or `FAIL`

Precedence:

1. `insufficient_history`
2. `regressed`
3. `recovered`
4. `improving`
5. `declining`
6. `stable`

## Overall Direction Rules

Use a simple deterministic implementation:

- If insufficient snapshots: `insufficient_history`
- If more categories are improving/recovered than declining/regressed: `improving`
- If more categories are declining/regressed than improving/recovered: `declining`
- If all or most categories are stable: `stable`

Include a deterministic leadership summary:

- Improving with persistent bottleneck:
  - `The team is improving overall, but Assurance remains the most persistent delivery constraint.`
- Declining:
  - `The team's SDLC evidence is declining. Leadership should review the categories with recent regressions before approving additional release acceleration.`
- Stable but weak:
  - `The team is stable but not improving. The current bottleneck has persisted across multiple snapshots and likely requires deliberate investment.`
- Insufficient history:
  - `Not enough historical snapshots exist yet. Create snapshots over multiple delivery cycles to establish a trend.`

## Persistent Bottleneck

Use each snapshot's `primary_bottleneck`.

Ignore:

```text
None
No bottleneck
""
```

The most frequently occurring category is the persistent bottleneck.

Example:

```text
Assurance appeared as the primary bottleneck in 4 of 6 snapshots.
```

## Malformed Or Missing History

Behavior should be helpful:

- Missing history directory: render insufficient history with next action to run `bottleneck snapshot`, or return a clear error if that is consistent with the CLI.
- One snapshot: render insufficient history.
- Malformed snapshot: either ignore with a warning or return a clear error. Pick one deterministic behavior and test it.
- Mixed environments: filter by `--env`.
