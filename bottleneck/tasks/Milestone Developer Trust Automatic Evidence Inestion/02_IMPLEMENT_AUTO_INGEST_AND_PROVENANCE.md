# Codex Prompt 02: Implement `bottleneck ingest --auto` and evidence provenance

## Objective

Make Bottleneck automatically ingest evidence from files discovered in the repo, while adding provenance metadata so developers trust where evidence came from.

This builds on `bottleneck discover` from Prompt 01.

## Required behavior

Add:

```bash
bottleneck ingest --auto
```

Also support:

```bash
bottleneck ingest --auto --dry-run
bottleneck ingest --auto --format json
bottleneck ingest --auto --merge
```

The auto-ingest command should:

1. Run discovery logic internally.
2. Select supported evidence files.
3. Convert them into Bottleneck evidence files.
4. Write to default Bottleneck evidence locations.
5. Preserve source/provenance metadata.
6. Print a summary of what was ingested, skipped, and unsupported.

## Supported evidence types for this prompt

Implement auto ingestion for evidence already supported by the repo:

- Cucumber JSON
- SARIF / CodeQL SARIF
- generic test summary JSON
- telemetry JSON

Also add v1 support for:

- JUnit XML
- coverage/lcov.info

If JUnit or coverage support is too large, implement minimal normalization with tests.

## Required default output paths

Use existing output paths when possible:

```text
bottleneck/assurance/results.json
bottleneck/security/guardrails.json
bottleneck/execution/telemetry.json
```

If coverage is implemented separately, write it to:

```text
bottleneck/assurance/coverage.json
```

But prefer merging coverage-derived evidence into `bottleneck/assurance/results.json` if that fits the current design.

## Evidence provenance requirements

Every normalized evidence item generated by ingestion should include as much of this metadata as possible:

```json
{
  "id": "ASSURANCE-001",
  "type": "cucumber",
  "source": "reports/cucumber.json",
  "generated_by": "cucumber",
  "generated_at": "2026-05-01T18:30:00Z",
  "ingested_at": "2026-05-01T18:32:00Z",
  "refs": ["BEHAVIOR-003"],
  "status": "pass",
  "confidence": "high",
  "provenance": "tool-generated"
}
```

Field guidance:

- `source`: relative path to the input file.
- `generated_by`: tool name such as `cucumber`, `sarif`, `junit`, `coverage`, `telemetry`.
- `generated_at`: from source file when available; otherwise omit or use file modified time if deterministic enough for tests.
- `ingested_at`: current time; make injectable in tests if possible.
- `confidence`: `high`, `medium`, or `low`.
- `provenance`: `tool-generated`, `manual`, or `inferred`.

Do not break readers that expect older evidence schema. Use additive fields only.

## Ref inference rules

Developers should not need to manually map everything on day one.

Implement light ref inference:

1. If a Cucumber scenario or tag includes something like `@BEHAVIOR-003`, add `BEHAVIOR-003` to refs and mark confidence `high`.
2. If test name includes `BEHAVIOR-003`, add it to refs and mark confidence `high`.
3. If no explicit behavior ID exists, do not invent a ref. Leave refs empty and lower confidence.
4. If future inference is added from names/paths, mark provenance `inferred` and confidence `low`.

## JUnit XML v1 requirements

Add:

```bash
bottleneck ingest junit --file reports/junit.xml
```

JUnit v1 should parse common JUnit XML forms:

```xml
<testsuite tests="2" failures="1" skipped="0">
  <testcase classname="PaymentTest" name="BEHAVIOR-003 retries failed payment" time="0.1"/>
  <testcase classname="LoginTest" name="login rejects invalid password" time="0.2">
    <failure message="failed" />
  </testcase>
</testsuite>
```

Also support `<testsuites>` containing multiple `<testsuite>` elements.

Normalize to assurance evidence with:

- total tests
- passed count
- failed count
- skipped count
- status `pass`, `fail`, or `warn`
- refs inferred from test names/class names
- source/provenance fields

## Coverage v1 requirements

Add:

```bash
bottleneck ingest coverage --file coverage/lcov.info
```

LCOV v1 should parse lines such as:

```text
TN:
SF:src/payment.ts
DA:1,1
DA:2,0
end_of_record
```

Compute a simple line coverage percentage:

```text
covered_lines / executable_lines
```

Normalize to assurance evidence with:

- status `pass` if coverage is >= configured threshold if available, otherwise status `warn`
- source/provenance fields
- confidence `medium`

Do not make coverage block release by itself unless existing scoring config already supports that behavior.

## Auto-ingest selection logic

When multiple files of the same type are found:

- Ingest all supported files by default.
- Merge into the appropriate output file.
- De-duplicate evidence entries by source path + ID when possible.
- Print skipped unsupported files clearly.

Example output:

```text
Bottleneck auto-ingest

Ingested:
  ✓ reports/cucumber.json -> bottleneck/assurance/results.json
  ✓ reports/codeql.sarif -> bottleneck/security/guardrails.json
  ✓ reports/telemetry.json -> bottleneck/execution/telemetry.json

Skipped:
  - coverage/cobertura.xml: detected but not supported yet

Warnings:
  - reports/junit.xml has no explicit BEHAVIOR-* refs; evidence confidence is medium.

Next action:
  Run bottleneck assess to view maturity and bottleneck diagnosis.
```

## Files likely to change

- `cmd/ingest.go`
- `cmd/ingest_test.go` or new tests
- `internal/ingest/*`
- `internal/discover/*` if shared discovery result types need enhancement
- `internal/models/*`
- `internal/validator/json_quality.go` to recognize provenance fields as quality/context

## Implementation constraints

- Keep all existing explicit ingest subcommands working.
- Additive schema changes only.
- No network access.
- No dependency on GitHub API.
- Do not require Bottleneck to be initialized before auto-ingest; create needed output directories.
- Preserve `--dry-run` behavior.
- `--dry-run` must not write files.

## Tests to add

Required tests:

1. `ingest --auto` uses discovery and writes assurance/security/execution evidence.
2. `ingest --auto --dry-run` writes nothing and reports what would be ingested.
3. Cucumber evidence includes source, generated_by, ingested_at, confidence, and provenance.
4. SARIF evidence includes source, generated_by, ingested_at, confidence, and provenance.
5. Explicit `@BEHAVIOR-003` tags are added to refs with high confidence.
6. JUnit XML parser handles both `<testsuite>` and `<testsuites>` roots.
7. JUnit test names with behavior IDs generate refs.
8. LCOV coverage percentage is calculated correctly.
9. Existing ingest tests still pass.
10. `go test ./...` passes.

## Acceptance criteria

- A new repo with reports can run `bottleneck ingest --auto` successfully.
- Auto-ingest output tells developers what was ingested and what was skipped.
- Normalized evidence includes provenance fields.
- Existing explicit ingestion behavior remains intact.
